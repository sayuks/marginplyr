# Public-interface bug hunt after the SQLite materialization changes

Investigated: 2026-09-26
Baseline: `7bd7b7c8814d2cb457538056de34ed77bce8058b`

Five independently reproducible defect families were found. The package's full
testthat suite passed at this baseline. No package implementation or test-suite
file was changed by this investigation.

## Reproduction and environment

Run from the repository root:

```sh
Rscript investigation/bug-hunt-2026-09-26.R
```

The script asserts intended behavior, rather than asserting the presence of a
bug. At the investigated commit all five findings failed their assertions and
the script exited with status 1. Each finding can be selected separately with
`sqlite`, `frame`, `unpack`, `join`, or `projection` as an argument. Controls run
before the failing assertion. SQLite writes are confined to an in-memory
connection. The script does not alter the package namespace.

The measured environment was R 4.6.1, dplyr 1.2.1, dbplyr 2.6.0, dtplyr 1.3.3,
data.table 1.18.6.1, RSQLite 3.53.3, DuckDB 1.5.5, Arrow 25.0.1, and testthat
3.3.2. These are measurements of that installation, not minimum-version claims.

## 1. P1: SQLite materialization converts display labels into numeric values

```r
con <- DBI::dbConnect(RSQLite::SQLite(), ":memory:")
source <- dplyr::copy_to(con, data.frame(g = 1L), "source")
query <- expand_with_margins(
  source, .grouping = rollup(g), .margin_label = "01", .id = "sid"
)
dplyr::collect(query)$g                         # c("1", "01")
saved <- dplyr::compute(query, name = "report")
dplyr::collect(saved)$g                         # c(1L, 1L)
DBI::dbGetQuery(con, "PRAGMA temp.table_info(report)")
DBI::dbGetQuery(con, "SELECT typeof(g), quote(g) FROM temp.report")
DBI::dbDisconnect(con)
```

The destination's `g` column was declared `INT`, and both stored values were
integer `1`. No warning was raised. This was a loss of the stored label, not
merely a different R class on retrieval. With the default `"Total"` label and
the detail row first, collection instead returned `c(1L, 0L)` with a mixed-type
warning. Reopening the result could not recover the original `"01"` spelling.

The path in [expand_with_margins()](../R/expand_with_margins.R) handed all
`operation$data_vars` to `finalize_margin_operation()` as source-type anchor
columns. These included dimensions already converted to character for a
non-missing Margin label. The finalizer's `text_dimensions` calculation in
[margin-operation.R](../R/margin-operation.R) excluded anchor columns from the
character declarations. The direct materializer in
[sqlite-typed-order.R](../R/sqlite-typed-order.R) created the destination from
that anchor, and SQLite applied its numeric affinity to the inserted labels.

A 240-case matrix crossed integer/double source dimensions, labels `"Total"`,
`"01"`, `"1e2"`, `NULL`, and `NA_character_`, summary/expansion, all three sort
options, presence/absence of `.id`, and rollup/one-set plans. It found 62
direct-versus-materialized type or value mismatches in the grouping dimension
`g`; it did not compare every result column. Both typed-missing label
controls matched throughout. Summary rollups with text labels matched; one-set
summary and expansion with `.id` also lost character type on materialization.
In those one-set cases the direct result was already character even though no
omitted-dimension row existed.

Historical execution in separate git archives established the recent boundary:

| Case | `d6e98f7` before #669 | `1df2bd4` after #669 | Investigated HEAD after #671 |
| --- | --- | --- | --- |
| Sorted expansion, numeric dimension, text label | Materialization refused by containment | Incorrect numeric destination | Incorrect numeric destination |
| Unsorted expansion with `.id`, label `"01"` | Preserved `c("1", "01")` | Preserved `c("1", "01")` | Stored `c(1L, 1L)` |
| One-set summary with `.id` | Materialization refused by containment | Character-to-integer change | Character-to-integer change |
| One-set expansion with `.id` | Preserved character | Preserved character | Character-to-integer change |

The relevant gap in
[test-sqlite-declared-boundary.R](../tests/testthat/test-sqlite-declared-boundary.R)
and [test-sqlite-b-direct-compute.R](../tests/testthat/test-sqlite-b-direct-compute.R)
was the intersection of **numeric dimension, text label, and materialization**.
Their expansion/one-set fixtures primarily used character `g`; an integer
payload `x` did not exercise conversion of a dimension. A regression assertion
needs both direct/materialized equality and inspection of stored values, since
driver coercion alone can hide the affinity problem. The affected contract is
[ADR 0031](../design/adr/0031-preserve-sqlite-typed-dimensions-under-margin-order.md).

## 2. P2: frame output prediction rejects names that are not outputs

```r
data <- tibble::tibble(g = "a", x = 1)
summarize_with_margins(
  data, tibble::tibble(g = NULL, total = sum(x)),
  .grouping = grouping_set(g)
)
# Summary results cannot overwrite grouping column: g
```

Ordinary `dplyr::summarise(..., .by = g)` returned `g = "a", total = 1`.
Wrapping the identical frame constructor in a caller function also succeeded
through the Margin verb. The literal constructor had no output column `g`.

`known_data_frame_output_names()` in
[summary-selections.R](../R/summary-selections.R) treated constructor argument
names as output names after removing formal control arguments. It did not
account for omitted NULL tibble columns, frame/matrix expansion, or name repair.
The same false refusal was measured for:

- `data.frame(g = data.frame(total = sum(x)))`, whose output was `total`;
- a named matrix `g`, whose outputs were `g.lo` and `g.hi`;
- `tibble(g = sum(x), .name_repair = function(nm) paste0(nm, "_out"))`,
  whose output was `g_out`;
- `data.frame("a b" = sum(x))` with `.id = "a b"`, where the actual output
  name was `a.b` and no `.id` collision existed.

The first failing decision was the static pre-execution collision check, before
any branch ran. Real dynamic collisions were still refused in the control.
The missing tests in
[test-summarize-operation.R](../tests/testthat/test-summarize-operation.R) were
constructor **argument names versus actual output schema**. Recent #628/#629
coverage addressed control arguments and ordinary function lookup, but did not
cover these shape changes. No introduction commit was established for this
family. [ADR 0028](../design/adr/0028-expand-a-data-frame-summary-marginplyr-named.md)
describes the actual-value boundary and the runtime collision checks.

## 3. P2: predicting across names executes `.unpack` before summary evaluation

A one-row, one-set reproduction in the script gave an `.unpack` callback an
evaluation counter and made the summary read that counter. Ordinary dplyr ran
the callback once and returned `x = 2`; marginplyr ran it twice and returned
`x = 3`. There was no extra grouping-set evaluation to explain the difference.

The extra call was traced through `predictable_local_across_names()` to
`known_across_output_names()` and `across_unpack_is_false()` in
[summary-selections.R](../R/summary-selections.R). The latter used
`rlang::eval_tidy()` on the original expression. The expression remained in the
summary for dplyr to evaluate again. The count was not caused by a repeated
summary function or by the public wrapper's argument matching.

A second reproduction used an `.unpack` function that returned FALSE on its
first call and TRUE thereafter. With
`across(x, ~ tibble::tibble(value = sum(.x)), .unpack = unpack())`, ordinary
dplyr returned a packed column `x`; marginplyr returned an unpacked `x_value`
column. Thus the extra evaluation could alter the output schema as well as
caller state and numeric values.

Separate source archives located the single-set local regression within #627:
the parent of `106db49` and `106db49` itself passed the counter assertion;
`16358af` ("Preserve early checks for bound unpack FALSE"), `438ea7b`, and the
investigated HEAD failed it. The existing tests covered literal/bound FALSE and
the resulting predicted names. They did not assert the evaluation count of a
call or active binding used for `.unpack`. Bound-value support therefore needs
a regression test that distinguishes reading a known value from running an
arbitrary expression during planning.

## 4. P2: dtplyr shares parse comparison operators inside fixed-key names

```r
data <- tibble::tibble(`a<b` = c("A", "A"), g = c("x", "y"),
                       value = c(1, 3))
query <- summarize_with_margins(
  dtplyr::lazy_dt(data), total = sum(value),
  fraction = share_of_total(total),
  .by = `a<b`, .grouping = rollup(g)
)
dplyr::collect(query)
```

The expected fractions were `0.25, 0.75, 1`. Collection failed with
`argument specifying columns received non-existing column(s): cols[1]='a'`.
Parent shares failed independently, with `cols[2]='a'`. Ordinary dtplyr
aggregation and Margin aggregation without shares succeeded on the same input.
Names containing `>`, `<=`, `>=`, `==`, and `!=` also reproduced the failure.

The internal share join passed these names to data.table's `on` parser.
`dtplyr_join_names()` in [share.R](../R/share.R) only activated its temporary
alias mapping for literal backticks. A diagnostic experiment aliasing every
join key made the public reproduction return the expected values. This was an
upstream parsing behavior exposed by the package's internal join; the caller
had not requested a non-equi join.

The test "dtplyr shares join fixed keys containing literal backticks" in
[test-share-backends.R](../tests/testthat/test-share-backends.R) exercised the
escape path for backticks alone. Comparison-operator spellings, and separate
Parent/Total requests with those fixed keys, were missing.

## 5. P2: dtplyr ordering silently renames `.BY` while removing its internal ID

```r
data <- tibble::tibble(g = c("x", "y"), .BY = c(1, 3))
query <- expand_with_margins(
  dtplyr::lazy_dt(data), .grouping = rollup(g), .sort = "last"
)
as.character(dplyr::tbl_vars(query)) # c("g", ".BY")
names(dplyr::collect(query))         # c("g", "BY")
```

No share expression was needed. Adding an ordinary `BY` column to the input
made collection fail with duplicate output names. Passing `.id = "set"`
preserved `.BY` and succeeded. Summary outputs named `.BY` exhibited the same
rename under Margin order. No silent numeric-value corruption was established
for this family.

`order_margin_result()` in [margin-operation.R](../R/margin-operation.R)
arranged the result and then removed the internal Grouping set identifier.
dtplyr fused the projection into a form equivalent to
`DT[order(...), .(g, .BY)]`, and data.table gave the unnamed `.BY` expression
the name `BY`. An ordinary dtplyr `arrange()` followed by `select()` reproduced
that upstream behavior too. This is an integration defect at a public Margin
result boundary: the package-created projection changed a caller's column name
and disagreed with its own declared schema.

The same automatic projection produced locked-binding errors for `.I`, `.SD`,
`.GRP`, and `.NGRP`, although their unsorted Margin expansions succeeded.
`.EACHI` passed both forms. `.N` failed even without ordering and was classified
as an existing upstream input restriction, not an additional Margin-order bug.

The missing dimension in
[test-margin-order.R](../tests/testthat/test-margin-order.R) was data.table
special names combined with the package's hidden-ID removal. The recently
fixed eager data.table expansion path from #664 passed the differential tests;
this finding concerned lazy dtplyr translation, a different path.

other defects.

The DuckDB value comparisons sorted rows and excluded attributes; they did not
establish equality of all result metadata. Non-finite aggregate values were
outside that random comparison, consistent with the backend-specific boundary
documented for shares. The Arrow probes observed results and conditions, not
an instrumented trace of every execution entry point. The local/data.table
comparisons normalized the outer frame class and row names; refusal on both
sides was treated as a matching outcome.

The common weakness was combination coverage. A line being executed did not
establish preservation of values and schema across text-label conversion,
materialization, callback evaluation, or backend parser metacharacters.
The strongest regression tests would compare direct versus materialized data,
declared versus collected names, and a single grouping set versus ordinary
dplyr, with negative controls at each boundary.

This investigation did not exercise a live PostgreSQL server, other operating
systems, or other installed dependency versions. It did not rerun strict line
coverage, a source-tarball check, or website rendering: no package-affecting
change was made. The new files were investigation evidence, excluded from the
source package by `.Rbuildignore`; they were not a substitute for adding
regression tests with later fixes.
