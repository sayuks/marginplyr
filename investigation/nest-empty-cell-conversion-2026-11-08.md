## Finding: registered conversion replaced the singleton empty-cell schema

For a keyless empty dtplyr input, `nest_by_with_margins()` first collected the
ordinary empty Nest result, then created its documented singleton cell from
the prepared schema. That fallback passed a freshly generated tibble through
`data.table::as.data.table()`. A registered `as.data.table.tbl_df` replacement
therefore received the generated cell and could replace all its columns.

The smallest witness used one zero-length integer column, `rid`, and a
replacement returning a zero-row data.table with character column `injected`.
The result retained one outer row, a zero-row cell, integer `.id = 1L`, and
correct row-wise grouping metadata, but its cell had `injected` instead of
`rid`. There was no warning or error. An outer/cell cardinality check alone
would accept it.

The [Nest reference][nest-reference], under *Relationship to tidyr and dplyr*,
promised cells holding the input's non-key columns, including the empty-input
exception for the row-wise verb. [ADR 0016's converter amendment][converter]
placed generated payload conversion on marginplyr's side of the ownership
boundary. The receiver was generated by marginplyr, rather than being a custom
input subclass whose conversion belonged to the caller. Replacing that
receiver's schema did not follow from delegation of arbitrary attributes or
from the permitted difference in backend cell classes.

| Single-condition control | Observed outcome under registration |
| --- | --- |
| Native collection of the original lazy input | Original columns/types; zero callbacks. |
| Empty `nest_with_margins()` | Zero outer rows; zero callbacks. |
| Empty `nest_by_with_margins()` with a fixed key | Zero outer rows; zero callbacks. |
| Populated keyless row-wise Nest | Original payload; zero callbacks. |
| Local empty keyless row-wise Nest | Original payload schema; zero callbacks. |
| Empty keyless dtplyr row-wise Nest | Replaced cell schema; one callback. |
| Same lazy input after restoring registration | Original payload schema. |

The coordinator independently used integer `code` and Date `day` payloads;
both disappeared into a single logical `replaced` column. A third process
used character `sector`, integer `receipt` and Date `stamp`, custom `.key`
and `.id`, and both initially empty and filtered-to-empty inputs. Each failing
call invoked the replacement once. All native, local, keyed-empty, populated
and restoration controls passed, and source data.table serialization remained
unchanged. Observed-result reproductions exited 0; desired-schema assertions
exited 1 after the controls and registration restoration completed.

A further 288 comparisons registered either the tibble-specific method or its
inherited data-frame method, using initial/filtered empty inputs, identifier
choices, custom list-column names, both keep values, all sort values and
absent/explicit empty specifications. All replaced the cell schema; restoring
registration restored each schema and type. Filter predicates ran once and
source bytes stayed unchanged. Four name-conflict controls refused before
calling the converter.

The standalone minimum, environment and acceptance criteria are in #1503.
The ticket covered one complete fallback repair and public regression, with
no blockers or new dependency prerequisite, labelled `bug` and
`ready-for-agent` under `to-tickets`.

## Existing cause: top-level aliases lost authored empty positions

A top-level alias of a Grouping constructor still lost an authored empty
position followed by an empty splice:

```r
gs <- grouping_set
x <- data.frame(g = c("E", "W"), rid = 1:2)
nest_with_margins(x, .grouping = gs(g, , !!!list()))
# Accepted: two cells, instead of the Argument 2 refusal.
s <- gs(g, , !!!list())
nest_with_margins(x, .grouping = s)
# Argument 2 of `grouping_set()` is empty.
```

The directly spelled constructor correctly refused the same call after the
#1489 repair. Valid aliases, genuine trailing commas, nonempty suffix splices
and stored specifications retained their expected behavior. The public
`.grouping` contract accepted any expression returning a specification;
constructor-spelling restrictions applied to nested positions instead.

Forty alias/factory, first/interior-position, local/dtplyr and five-consumer
comparisons admitted the invalid input; fifty normal/refusal controls matched.
The coordinator independently confirmed both Nest verbs and inspection,
including a keyless case incorrectly admitted as a single Grand total cell.
Its desired-refusal assertion exited 1. Source serialization was unchanged.

The cause was the same outer-capture/trailing-omission boundary as #1489:
`mark_grouping_empty_args()` marked statically recognized constructor calls,
and the alias did not receive its marker. This was recorded as a residual
path of that closed report, rather than counted as a second independent
cause or published again. Its [additional evidence][capture-comment] named
the tested post-repair main and the missing regression condition.

were written by hand, without taking expected sets from inspection or the
compiler. A simple partition of source positions by fixed/included keys and
source-row extraction supplied expected cells. Explicit selections kept the
tracing row ID out of the key selection. Checks matched each outer key and
Grouping set identifier to its cell and compared row-ID multisets, values,
columns, original retained keys and guaranteed types. They did not require a

True payload-free fixtures did not add an ID that would change their meaning;

The coordinator's first label frontier incorrectly treated same-membership
cells in different sets as uniquely identifiable without `.id`, and compared
numeric source keys directly with their documented character display under a
string label. Those harness errors were corrected by keeping `.id` and
comparing displayed active values appropriately; the 576 distinct corrected
cases were executed again. The initial exploratory count was not reused.
A's oracle initially distinguished signed zero by serialization and treated
packed-frame attribute order as value inequality; 144 targeted corrected cases
matched. Another 24 data.table oracle cases used join syntax instead of column
extraction and matched after correction. C's empty oracle initially fabricated
a key through `paste0(character(0))`; all 334 boundary cases were rerun with
an actual empty key vector and matched. These were harness corrections, not
package findings. The fallback probe likewise compared caller-owned source
bytes, not an environment containing changing execution locals.
C's first multiplicity probe added a `mutate()` tracing operation that was
itself refused by metadata admission; those sixty refusals were kept separate
and replaced with the existing-ID controls above.
