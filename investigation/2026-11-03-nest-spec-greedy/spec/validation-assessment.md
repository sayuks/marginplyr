# Independent assessment of display-conversion findings

Investigated: 2026-11-03
Baseline: `4b34fdecb2d8a41034b3d9b5d5af8e51592555e1` (`main`)

This follow-up independently replayed the local track's two conversion findings
against the specification track's separate archived source copy. It changed no
package code or permanent test. Both were judged suitable for independent repair
tickets, with no blocking edge between them. The coordinator owned duplicate
search and publication.

## Empty hms display conversion

The command below ran with the archived source as its working directory:

```sh
Rscript /private/tmp/marginplyr-nest-spec-20261103/investigation/2026-11-03-nest-spec-greedy/coordinator/empty-hms-independent.R --assert
```

It returned terminal exit 1 (retained execution `85506`), at its desired-behavior
assertion. `validation-hms.log` retained the observed errors for both nesting
verbs, expansion and summary. Each reported an incompatible logical/character
branch combination. Its populated and typed-missing controls had succeeded;
source serialization was unchanged.

`validation-conversion-controls.R` separated upstream conversion from package
assembly. With hms 1.1.4, `as.character.hms()` delegated to
`vec_cast(x, character())`, and an empty hms value answered with `logical(0)`.
Ordinary `mutate(g = as.character(g))` accepted that logical column, and native
nesting accepted the original empty hms key. A single `grouping_set(g)` through
`nest_with_margins()` returned an empty `g <lgl>` column. Giving the same source
an explicitly bare `character(0)` column before entry made rollup nesting
succeed with `g <chr>`.

The upstream empty conversion was the trigger, but the observed failure was
not a user's expression being refused by its engine: conversion answered
without an error, and package-generated branches then disagreed. The
`Display labels and grouping identity` section of the Margin reference said
that non-missing labels converted ordinary grouping dimensions to character.
Both the logical single-set result and the rollup assembly error violated that
contract for this valid local input. ADR 0033's explicit output-type table did
not include ordinary dimensions, so that ADR alone was not used as the basis
for the assessment.

## One-dimensional rvar display and collision checking

The independent fixture used one `posterior::rvar` key with four draws of one.
Native `tidyr::nest()`, both Margin nesting verbs with a typed-missing label,
and both verbs with collision checking disabled all returned one cell retaining
`row_id = 1L`. The default checked Margin calls failed in their generated
collision summary.

The conversion itself answered with a one-dimensional character array. Its
comparison to `"Total"` was a one-dimensional logical array, and
`dplyr::if_else()` rejected that condition: `condition` must be a logical
vector, not a logical 1D array. Reading the converted values as a plain vector
produced the unambiguous collision counts: zero for `"Total"`, one for the
actual converted value. No random draw or ambiguous statistical comparison was
needed; the check concerned the already-defined display strings.

This was a collision-adaptation defect, distinct from the hms zero-length type
issue. The predicate was generated by marginplyr for an admitted scalar-vector
key, and not written by its caller. It therefore could not be dismissed as a
backend rejecting a requested user expression. It was also distinct from the
reference's restriction on matrix or higher-dimensional array grouping keys:
this admitted rvar was one-dimensional, and its ordinary grouping and unchecked
Margin operations both worked.
