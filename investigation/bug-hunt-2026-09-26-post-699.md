# Bug hunt after the evaluation and backend-name repairs

Investigated: 2026-09-26
Baseline: `af3ce0743c8b2e974b622126b428fa019fb53779`

Five independent repair units were reproduced after #699. Seven minimized
public-API probes failed their intended-result assertions. The full existing
testthat suite and all twenty probes from the three earlier September 26
investigations passed. No package implementation or package-test file was
changed; this investigation prepared implementation tickets rather than fixes.

## Reproduction

From the repository root:

```sh
Rscript investigation/bug-hunt-2026-09-26-post-699.R
```

An optional argument selects `unpack_true`, `unpack_false`, `first_packed`,
`pronoun_data`, `pronoun_env`, `dtplyr_share`, or `dtplyr_projection`.
Each probe establishes ordinary-backend and non-triggering Margin controls
before asserting the intended result. The combined command took about one
second and exited 1 with all seven failures. It changes no package namespace.

The measured installation was R 4.6.1, dplyr 1.2.1, dbplyr 2.6.0, dtplyr 1.3.3,
data.table 1.18.6.1, RSQLite 3.53.3, DuckDB 1.5.5, Arrow 25.0.1, tibble 3.3.1,
rlang 1.3.0, and testthat 3.3.2. These versions describe the experiment, not
minimum supported versions.

## 1. P2: dynamic unpack changes ordinary function-argument evaluation

The `unpack_true` probe defines a pure function factory whose argument is
`dplyr::n()`. It captures that scalar and returns a function adding it to a
column's sum. With groups of sizes one and two and values 1, 10, 20, ordinary
dplyr and literal-TRUE Margin unpacking return 2 and 32. Changing only the
Margin argument to `identity(TRUE)` returns 2 and 31. No callback side effect,
share, ordering, identifier, or Grand total set is needed.

`wrap_local_frame_summaries()` in `R/summary-selections.R` wraps dynamic
unpacking in `local_assigned_summary_value()`, then caches `.fns` and `.unpack`
through `local_once_across_arg()`. Its dynamic test includes TRUE and string
values. The first group's function is consequently reused in later groups.
A clean archive of `241d3fa`, before #699, passed the same TRUE probe; this
part was a regression introduced by the repair in `64b0f76`.

The `unpack_false` probe needs just one row, x = 1, and a scalar-returning
factory. Ordinary dplyr and literal FALSE evaluate the factory while expanding
the top-level call, where this `n()` is zero, and return 1. Dynamic FALSE
executes the factory inside the first group's evaluation, where `n()` is one,
and returns 2. #693's invocation-count test passed even though this phase was
wrong. The same FALSE probe also failed before #699: that archive returned 2
and 32 in the two-group example, while the investigated baseline returned 2
and 31. This was a remaining evaluation-context defect, not a new FALSE
regression.

A corrected 360-case differential matrix crossed three local frame classes,
FALSE/TRUE/string unpack values, literal/expression/ordinary-bound/delayed/
active spellings, scalar/frame outputs, single-set/rollup plans, and an
unrelated Total share. It compared ordinary dplyr branches, preserving their
per-branch argument evaluation, with the corresponding Margin result. Ninety-six
TRUE/string cases and seventy-two FALSE cases differed; 192 controls agreed.
The earlier exploratory version included invalid shares without a Grand total
set; those comparisons were discarded before the corrected count.

[ADR 0019](../design/adr/0019-resolve-contextual-helper-names-by-static-spelling.md)
leaves `n()` and ordinary functions to their ordinary evaluation. The repair
must preserve that phase and scope, as well as invocation counts, without
removing the actual-value frame protections in
[ADR 0028](../design/adr/0028-expand-a-data-frame-summary-marginplyr-named.md).
The TRUE and FALSE probes belong to one repair unit: both test whether wrapping
an ordinary top-level across preserves its argument evaluation.

## 2. P2: the first packed selection runs outside its data mask beside a share

The `first_packed` probe starts with a caller-named `packed = across(...)`,
then defines a numeric `total`, then a Total share of `total`. Its selector
uses ordinary `dplyr::n()` to select x from a one-row input. Ordinary dplyr and
the Margin call without the unrelated share return packed x = 1. Adding the
share raises `Must only be used inside data-masking verbs` during planning.
Neither another grouping set nor callback side effects are needed.

`plan_summary_expressions()` in `R/summary-selections.R` leaves the first
ordinary selection eager when any share is present. It is therefore rewritten
against the selection proxy outside dplyr's actual summary mask. The #694
repair protects packed selections after a preceding summary, but the first
ordinary summary takes this earlier route. The packed output was unrelated to
the share source in both cases; making it first did not make it eligible as a
share source.

All 36 narrowed comparisons failed: three local frame classes, Parent/Total
shares, one/multiple detail groups, and direct/callback/active-binding
selectors. A separate callback experiment also changed packed columns and
selector counts when the unrelated share was added. The documented exclusion
of preceding share outputs from ordinary selection was retained in the oracle;
selecting a constant replacement for that output would not be a valid control.

The repair should defer this unrelated packed selector to ordinary execution
regardless of its position. It must retain packed-source refusal and share
eligibility/dependency checks. This is independent of finding 1: no unpack
argument or factory is involved.

## 3. P1: text conversion replaces a .data grouping value with an environment

The `pronoun_data` probe uses one row `.data = "a", value = 1L` and one
Grouping set retaining that dimension. The expected group is "a"; the Margin
result instead contains the string `"<environment>"`. The summary value is
still 1, so checking only row counts or aggregates misses the corruption.
The same ordinary dplyr grouping, and the Margin call with a missing label,
retain "a". No omitted set is required. The sibling `pronoun_env` probe raises
`cannot coerce type 'environment' to vector of type 'character'` for `.env`.

`label_margin_branch()` in `R/margin-label.R` generates
`across(all_of(safe_columns), as.character)` for included labelled dimensions.
Ordinary across also exhibits the pronoun lookup, whereas explicit
`.data[[name]]` reads the column. A caller requesting grouping or nesting did
not supply across; the package's generated conversion introduces the failure.
The `dtplyr_safe_column_reads()` wrapper is inactive on local frames.

A 2,304-call matrix crossed `.data`/`.env`/ordinary names, character/numeric/
factor/NA-level-factor types, empty/populated inputs, one-set/rollup plans,
three sorts, observed-label checking on/off, text/missing labels, and all four
Margin verbs. It found 96 corrupt `.data` results and 192 `.env` errors. All
2,016 other cases passed, including every factor case and missing-label control.
Factors take the explicit encoding path instead of the across conversion.
Empty `.env` inputs also failed. Fixed and payload pronoun names were accepted
in the separate nesting name experiment.

The same minimal probe failed in a clean `241d3fa` archive; an exact introduction
boundary was not established. #698 repaired `.data` as a summary *output*, and
existing data-pronoun tests used it as a fixed key. Neither reaches this Margin
dimension conversion. One repair should preserve both pronoun-named dimensions
through all four verbs, including their actual keys, labels, and ordering.

## 4. P2: contextual shares read dtplyr special grouping dimensions unsafely

The `dtplyr_share` probe uses `.N = "a", value = 2`. Ordinary dtplyr grouping
and a Margin rollup without a share both succeed. Adding a Total share of the
ordinary `total` summary fails at collection with
`cannot change value of locked binding for '.N'`. The local result has total
2 and share 1 in both the detail and Grand total rows. Parent shares fail too.
The caller's input was unchanged after failure in the scoped probes.

`summarize_margin_union()` in `R/grouping-adapter-union.R` copies retained
original dimensions into private share keys outside `dtplyr_safe_column_reads()`.
The resulting data.table expression reads the special name directly. Both
share kinds retain these keys for grouped-cardinality checks, so a Total share
also takes the path without needing parent matching.

All 240 comparisons failed across five names (`.N`, `.I`, `.SD`, `.GRP`,
`.NGRP`), Parent/Total shares, text/missing labels, fixed-key presence,
zero/one/three rows, and character/factor dimensions. This differs from #696's
special *summary-source* name and #695's ordinary grouping-key preparation.
The repair must preserve both kinds of shares, the original typed grouping
identity, lazy construction, and the unchanged caller input.

## 5. P2: dtplyr expansion reads special columns while putting keys first

The `dtplyr_projection` probe has input columns `.N, g`, with `.N = 1:2` and
g = a,b. Expanding `rollup(g)` with a missing label should preserve the payload
values twice and return columns `g, .N`. Collection instead raises the same
locked-binding error. Ordinary dtplyr union of the source and its missing-g
copy succeeds. So does the Margin call with the default text label.

The last select in `label_margin_branch()` puts fixed keys and dimensions
first. With no preceding mutation on a retained branch, dtplyr renders that
reorder as `DT[, .(g, .N)]`. The text-label branch's earlier mutation happens to
let dtplyr use `setcolorder()` instead. The output projection, rather than a
share or a label-value conversion, is the uncovered read.

A 378-case matrix crossed seven names, dimension/fixed/payload roles, three
label forms, zero/one/three rows, and no/last ordering. There were 216 failures:
all missing-label cases for `.N`, `.I`, `.SD`, `.GRP`, `.NGRP`, and `.BY`.
`.BY` raised a union column-name mismatch instead. All 126 text-label cases and
all 54 `.EACHI` cases passed; the sets overlap, giving 162 passing cases.
The caller input was unchanged in the minimized failure.

A separate ticket should preserve special names through required projection,
including carried payloads, empty inputs, and both NULL and NA labels. This
repair is independently verifiable from finding 4; it needs no share arithmetic
and can fail with an ordinary-named dimension.

The nesting membership oracle used inspection to enumerate expected sets; the
separate plan-algebra oracle expanded recursive specifications independently.

refused, and neither Arrow matrix instrumented all query execution entry points.

were not exercised. A passing finite matrix establishes only its listed scope.

The coordinating investigator independently reran each selected failure and its
controls. A second investigator independently checked both unpack probes and
the first-packed probe, including the before-#699 archive comparison. Existing open Issues and the relevant closed reports were inspected
to avoid duplicating unresolved work. No semantic blocking edge joins the five
repairs: their source files overlap, but each can land with its own public-API
regressions and preserve the other contracts. The two unpack manifestations
share one evaluation boundary; the two pronoun names share one conversion.

These investigation artifacts are excluded from the source package by
`.Rbuildignore`. No Package-affecting change, strict coverage run, source-tarball
check, or site render was part of this investigation. Implementation and package
regression tests belong to the resulting tickets.
